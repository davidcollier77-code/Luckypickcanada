# Harden gift-delivery error handling

This PR fixes delivery-state integrity and safe retry handling for paid gift emails.

- Replaces predictable lock token generation with `crypto.randomUUID()`.
- Uses an atomic Redis compare-and-delete script to release only the current lock owner's lock.
- Persists a pending state and fixed reveal before contacting Resend.
- Marks delivery as sent only after Resend accepts the request.
- Retries pending requests with the same payload and idempotency key inside a conservative 23-hour window.
- Requires manual reconciliation for stale or incomplete pending attempts.
- Adds regression tests for successful delivery, thrown/non-success responses, stable retries, stale attempts, Stripe failure, configuration/validation early exits, and lock release.
