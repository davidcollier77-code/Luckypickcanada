feat: add automated reviewer assignment and notifications to updater workflows

Adds automatic reviewer assignment and notification logic to the two
automated updater workflows:
1. Document Library Updater (.github/workflows/refresh-docs.yml)
2. Spec Kit Updater (.github/workflows/update-spec-kit.yml)

Changes:
- Added `issues: write` permission to both workflows to allow PR commenting.
- refresh-docs.yml:
  - Updates `gh pr create` to use `--reviewer davidcollier77-code`.
  - Added logic to fall back to a comment mention if reviewer assignment fails.
  - Added logic for when PR is updated via force-push: detects if a comment containing `<!-- notify-update:$COMMIT_SHA -->` exists, and if not, comments tagging the owner that the PR is ready for review.
- update-spec-kit.yml:
  - Adds `reviewers: "davidcollier77-code"` to `peter-evans/create-pull-request` parameters.
  - Checks outputs (`steps.cpr.outputs.pull-request-operation`) to conditionally execute two new steps:
    - If updated: uses GitHub CLI to add a comment with `<!-- notify-update:$COMMIT_SHA -->` if one hasn't been posted yet for that commit.
    - If created: verifies that a review request was attached and falls back to a comment mention if it wasn't.

Fixes the issue where automated PR updates go unnoticed.
