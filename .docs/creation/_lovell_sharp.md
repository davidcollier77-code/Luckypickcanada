lang="en" dir="ltr"><div class="content-panel astro-a7po4psb"><div class="sl-container astro-a7po4psb"><h1 id="_top" class="astro-bebwqqxs">High performance Node.js image processing</h1></div></div><div class="content-panel astro-a7po4psb"><div class="sl-container astro-a7po4psb"><div class="sl-markdown-content"><img src="/sharp-logo.svg" width="160" height="160" alt="sharp logo" align="right">
<p>The typical use case for this high speed Node-API module
is to convert large images in common formats to
smaller, web-friendly JPEG, PNG, WebP, GIF and AVIF images of varying dimensions.</p>
<p>It can be used with all JavaScript runtimes
that provide support for Node-API v9, including
Node.js &gt;= 20.9.0, Deno and Bun.</p>
<p>Resizing an image is typically 4x-5x faster than using the
quickest ImageMagick and GraphicsMagick settings
due to its use of <a href="https://github.com/libvips/libvips">libvips</a>.</p>
<p>Colour spaces, embedded ICC profiles and alpha transparency channels are all handled correctly.
Lanczos resampling ensures quality is not sacrificed for speed.</p>
<p>As well as image resizing, operations such as
rotation, extraction, compositing and gamma correction are available.</p>
<p>Most modern macOS, Windows and Linux systems
do not require any additional install or runtime dependencies.</p>

<div class="sl-heading-wrapper level-h2"><h2 id="formats">Formats</h2><a class="sl-anchor-link" href="#formats"><span aria-hidden="true" class="sl-anchor-icon"><svg width="16" height="16" viewBox="0 0 24 24" fill="currentColor"><path d="m12.11 15.39-3.88 3.88a2.52 2.52 0 0 1-3.5 0 2.47 2.47 0 0 1 0-3.5l3.88-3.88a1 1 0 1 0-1.42-1.42l-3.88 3.89a4.48 4.48 0 0 0 6.33 6.33l3.89-3.88a1 1 0 0 0-1.42-1.42m8.58-12.08a4.49 4.49 0 0 0-6.33 0l-3.89 3.88a1 1 0 1 0 1.42 1.42l3.88-3.88a2.52 2.52 0 0 1 3.5 0 2.47 2.47 0 0 1 0 3.5l-3.88 3.88a1 1 0 0 0 0 1.42 1 1 0 0 0 1.42 0l3.88-3.89a4.49 4.49 0 0 0 0-6.33M8.83 15.17a1 1 0 0 0 .71.29 1 1 0 0 0 .71-.29l4.92-4.92a1 1 0 1 0-1.42-1.42l-4.92 4.92a1 1 0 0 0 0 1.42"></path></svg></span><span class="sr-only" data-pagefind-ignore>Section titled “Formats”</span></a></div>
<p>This module supports reading JPEG, PNG, WebP, GIF, AVIF, TIFF and SVG images.</p>
<p>Output images can be in JPEG, PNG, WebP, GIF, AVIF and TIFF formats as well as uncompressed raw pixel data.</p>
<p>Streams, Buffer objects and the filesystem can be used for input and output.</p>
<p>A single input Stream can be split into multiple processing pipelines and output Streams.</p>
<p>Deep Zoom image pyramids can be generated,
suitable for use with “slippy map” tile viewers like
<a href="https://github.com/openseadragon/openseadragon">OpenSeadragon</a>.</p>
<div class="sl-heading-wrapper level-h2"><h2 id="fast">Fast</h2><a class="sl-anchor-link" href="#fast"><span aria-hidden="true" class="sl-anchor-icon"><svg width="16" height="16" viewBox="0 0 24 24" fill="currentColor"><path d="m12.11 15.39-3.88 3.88a2.52 2.52 0 0 1-3.5 0 2.47 2.47 0 0 1 0-3.5l3.88-3.88a1 1 0 1 0-1.42-1.42l-3.88 3.89a4.48 4.48 0 0 0 6.33 6.33l3.89-3.88a1 1 0 0 0-1.42-1.42m8.58-12.08a4.49 4.49 0 0 0-6.33 0l-3.89 3.88a1 1 0 1 0 1.42 1.42l3.88-3.88a2.52 2.52 0 0 1 3.5 0 2.47 2.47 0 0 1 0 3.5l-3.88 3.88a1 1 0 0 0 0 1.42 1 1 0 0 0 1.42 0l3.88-3.89a4.49 4.49 0 0 0 0-6.33M8.83 15.17a1 1 0 0 0 .71.29 1 1 0 0 0 .71-.29l4.92-4.92a1 1 0 1 0-1.42-1.42l-4.92 4.92a1 1 0 0 0 0 1.42"></path></svg></span><span class="sr-only" data-pagefind-ignore>Section titled “Fast”</span></a></div>
<p>This module is powered by the blazingly fast
<a href="https://github.com/libvips/libvips">libvips</a> image processing library,
originally created in 1989 at Birkbeck College
and currently maintained by a small team led by
<a href="https://github.com/jcupitt">John Cupitt</a>.</p>
<p>Only small regions of uncompressed image data
are held in memory and processed at a time,
taking full advantage of multiple CPU cores and L1/L2/L3 cache.</p>
<p>Everything remains non-blocking thanks to <em>libuv</em>,
no child processes are spawned and Promises/async/await are supported.</p>
<div class="sl-heading-wrapper level-h2"><h2 id="optimal">Optimal</h2><a class="sl-anchor-link" href="#optimal"><span aria-hidden="true" class="sl-anchor-icon"><svg width="16" height="16" viewBox="0 0 24 24" fill="currentColor"><path d="m12.11 15.39-3.88 3.88a2.52 2.52 0 0 1-3.5 0 2.47 2.47 0 0 1 0-3.5l3.88-3.88a1 1 0 1 0-1.42-1.42l-3.88 3.89a4.48 4.48 0 0 0 6.33 6.33l3.89-3.88a1 1 0 0 0-1.42-1.42m8.58-12.08a4.49 4.49 0 0 0-6.33 0l-3.89 3.88a1 1 0 1 0 1.42 1.42l3.88-3.88a2.52 2.52 0 0 1 3.5 0 2.47 2.47 0 0 1 0 3.5l-3.88 3.88a1 1 0 0 0 0 1.42 1 1 0 0 0 1.42 0l3.88-3.89a4.49 4.49 0 0 0 0-6.33M8.83 15.17a1 1 0 0 0 .71.29 1 1 0 0 0 .71-.29l4.92-4.92a1 1 0 1 0-1.42-1.42l-4.92 4.92a1 1 0 0 0 0 1.42"></path></svg></span><span class="sr-only" data-pagefind-ignore>Section titled “Optimal”</span></a></div>
<p>The features of <code dir="auto">mozjpeg</code> and <code dir="auto">pngquant</code> can be used
to optimise the file size of JPEG and PNG images respectively,
without having to invoke separate <code dir="auto">imagemin</code> processes.</p>
<p>Huffman tables are optimised when generating JPEG output images
without having to use separate command line tools like
<a href="https://github.com/tjko/jpegoptim">jpegoptim</a> and
<a href="http://jpegclub.org/jpegtran/">jpegtran</a>.</p>
<p>PNG filtering is disabled by default,
which for diagrams and line art often produces the same result
as <a href="https://pmt.sourceforge.io/pngcrush/">pngcrush</a>.</p>
<p>The file size of animated GIF output is optimised
without having to use separate command line tools such as
<a href="https://www.lcdf.org/gifsicle/">gifsicle</a>.</p>
