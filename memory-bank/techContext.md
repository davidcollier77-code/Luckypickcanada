# Technical Context

## QA checker suite
- `.github/workflows/pr-verification-report.yml` publishes the single consolidated PR verification report with exactly seven categories: QA Checker, DevSkim, PR Scope Verification, Protected File Changes, Verification Integrity, Governance and Workflow Verification and Dependency Health & Vulnerability Review. Statuses are limited to `PASSED`, `FAILED`, `WARNING` and `NOT RUN`; the report is a marker-first sticky comment updated in place by `.github/scripts/upsert_pr_comment.sh`, which refuses an unmarked, missing or over-60,000-byte body. The workflow also refreshes on owner `/approve-` comments, paginates check runs and dependency advisories, and publishes a `NOT RUN` placeholder if rendering fails so a stale pass cannot remain visible.
- `.github/scripts/pr_verification_report.py` builds the report from GitHub evidence. QA Checker keeps the exact pre-submission declaration, `review_pr_changes.py` findings, `checker_suite.py` test-quality and performance findings, and the full unit suite, TypeScript check, production build and both Playwright shards as supporting evidence. The changed-code findings and the former Visual QA summary are consolidated into that report rather than published as separate comments.
- DevSkim's scanner rules, scan globs and workflow triggers are unchanged. The exact-span suppression filter additionally accepts Spec Kit evidence JSON loopback data for DS162092 and the Lucky Meter readiness watchdog for DS172411, each rule- and path-scoped and validated against the reported span. The report reads the existing code-scanning alerts API with pagination (`--paginate --slurp`), so it counts the full open backlog instead of one page. Dependency Health & Vulnerability Review runs on every pull request: changed manifests/lockfiles are checked for consistency and matched against open dependency advisories, unchanged outdated dependencies never fail the PR, and an unreadable advisory source is `NOT RUN` rather than a pass. Dependabot remains the unchanged weekly updater and is not a prerequisite. The report workflow declares `vulnerability-alerts: read` so the seventh category can read Dependabot alerts; `security-events: read` covers code scanning only. Because the workflow runs under `pull_request_target` and checks out `main`, a permission change applies only after it reaches `main`, never to the pull request that adds it. `check_qa_pr_scope.py` still enforces exact paths, per-file purposes and owner approval digests, requires the exact words `Scope changed` for expansions, and no longer requires submitter browser evidence. `verify_pr_verification_status.py` supplies the current-head audit; the report fails closed on empty or malformed audit evidence and on an audit for another commit, so missing, skipped, stale or earlier-commit results are never reported as passed.

## Application Stack
- **Framework:** Next.js App Router 16.4.6, React 19.3.1 and TypeScript.
- **Runtime:** Node.js 26.x.
- **Cloudflare build tools (installed and verified 2026-11-26):** root package.json pins @opennextjs/cloudflare 1.20.19 and Wrangler 4.168.0; the lockfile resolves @opennextjs/aws 4.2.1, Miniflare 5.20261123.1-beta and Workerd 1.20261123.1. There is no global Undici override. Each Undici major resolves at or above its advisory floor: 6.29.1 (dotenvx), 7.30.2 (Wrangler, Miniflare, workers-utils) and 8.13.1 (jsdom). Wrangler's declared `undici: 7.30.2` edge is preserved exactly. The `minimatch@10 -> 11.0.1` override is retained because @typescript-eslint/typescript-estree@8.69.0 declares `^10.2.2`; its obsolete `minimatch@10.2.6>brace-expansion` selector was removed.
- **Package manager:** pnpm 10.30.3. Use the committed lockfile and pnpm; never use npm ci.
- **Styling and motion:** Tailwind CSS 4, Framer Motion, GSAP and existing Canvas-based visual effects.
- **Creative capability layer:** `app/lib/graphics/` is the automatic graphics/audio layer. `technologies.js` selects Three.js, Canvas 2D, an existing WebGL engine or DOM from declared requirements plus the shared probes and tier (reduced motion never downgrades the renderer); `experiences.js` is the single visual registry and derives hub resources from one descriptor; `runtime.js` returns one `start`/`stop`/`render`/`resize`/`dispose` lifecycle for every renderer; `canvas-surface.js`, `timeline.js`, `materials.js`, `lighting.js`, `particles.js` and `audio-sync.js` are the reusable building blocks; `components/graphics/CreativeSurface.jsx` and `app/lib/use-creative-experience.js` are the React bindings. The readiness hub gained `module` (lazy engine chunks via literal dynamic imports in `engine-chunks.js`), `texture` (fetch + `ImageBitmap`) and `model` (glTF HTTP preflight) adapters through `registerResourceAdapter` — no second preloader. The Lucky Meter and Card Reveal consume it through `useCreativeExperience`; at the time of Spec 193 their visuals, timing, sound and fallbacks were unchanged. Specs 199 and 200 later changed the Lucky Meter presentation, while the Card Reveal remained unchanged.
- **Sound reactivity and the Creative Workbench (spec 193 continuation):** `app/lib/graphics/audio-reactivity.js` taps the existing Howler/Web Audio mix with one shared `AnalyserNode` through a zero-gain branch (no new `AudioContext`, audible output unchanged) and produces a smoothed envelope (`level`, `bass`, `mids`, `highs`, `transient`, `peak`) with `bindLightRig`, `bindParticleField`, `bindValue` and `onBeat`. `reactiveAudio` in `technologies.js` enables it only when the browser can analyse audio and motion is allowed; `runtime.js` passes `frame.envelope` and `surface.reactive` for THREE and Canvas 2D surfaces. `workbench.js`, `workbench-runtime.js` and `components/graphics/CreativeWorkbench.jsx` provide the development-only `/workbench/creative` sandbox with deterministic scene/tier/seed/time controls, `window.__creativeWorkbench` inspection, PNG capture and a 404 gate in production unless `CREATIVE_WORKBENCH=1`. Howler cues declared `html5: true` are captured through a `MediaElementAudioSourceNode` on Howler's existing context when the browser supports it: the element feeds the context destination at unity (audible playback unchanged) and the shared analyser. Capture is refused for an unsupported API, a non-running context, a cross-origin element or an already-owned element, and releasing the analyser never disconnects a cue's audible path. `playHtml5Cue` and `audio.html5Sources`/`audio.html5Playing` in the workbench exist only for browser verification.
- **Graphics compatibility:** One shared, dependency-free layer at `app/lib/graphics-capabilities.js` supplies lazy Canvas 2D/WebGL/`Path2D` detection, safe context acquisition, a conservative device profile, reduced-motion/visibility helpers and context-loss watching. Renderers let the browser choose its own GPU or software rasterizer.
- **3D graphics toolkit (spec 193):** `three` 0.187.0 and `@types/three` 0.187.0 (both MIT) are installed and wrapped in `app/lib/graphics/`: `stage.js` (lazy `import('three')`, tiered renderer/scene/perspective camera, adaptive frame loop, reduced-motion static frame, context loss/restore, idempotent disposal), `effects.js` (tiered `EffectComposer` + `UnrealBloomPass` + `OutputPass` ACES/sRGB + `SMAAPass` from `three/addons`), `assets.js` (lazy uncompressed glTF/GLB loading) and `resources.js` (geometry/material/texture disposal). The Lucky Meter scene (`app/lib/lucky-meter/meter-scene.js`, registered as `lucky-meter`) is the production consumer; the Three.js chunk remains lazy and is requested only by that experience. WebGPU remains probe-only; the toolkit renders through WebGL and keeps the browser's backend choice. Usage rules and rejected alternatives are in `app/lib/graphics/README.md`.
- **Adaptive performance:** `app/lib/adaptive-performance.js` reads measured network throughput/latency (labels are only a fallback and never identify 5G), the cached device assessment, reduced motion and optional heap pressure, then resolves one plan (tier, frame rate, animation budget, prefetch/audio/image policies, parallel-request limit, release flag). One shared subscription serves every consumer, `createAdaptiveFrameLoop` governs ambient canvas cadence, and `registerReleasableResource` releases idle resources under memory pressure. Missing hints always resolve to the full experience. `app/lib/use-adaptive-plan.js` is the React binding.
- **Plan-aware frame diagnostics (spec 215 follow-up):** the observational monitor in `app/lib/adaptive-performance.js` keeps one sample window per existing rendering source (`adaptive-frame-loop`, `cosmic-engine`) and scales the 60 fps policy to the active plan's frame rate, so a 30 fps plan is healthy at 25 fps or better and critical below 14 fps. It reports `warming`/`healthy`/`strained`/`critical`/`paused`/`idle` with `measured`/`insufficient`/`unavailable`/`paused`/`stale` evidence, and `getPerformanceDiagnostics()` returns `{ plan, monitor, device }`; `window.__creativeWorkbench.getState()` (version 2) exposes it in the development Workbench. The consolidated report renders one informational `GOOD`/`NEEDS ATTENTION`/`BAD`/`NOT ENOUGH DATA` block outside the seven categories; it never changes category or PR status, and CI supplies no runtime frame sample.
- **Device assessment and frame observability (spec 215):** `app/lib/graphics-capabilities.js` exposes one cached `getDeviceAssessment()` (capability tier, confidence, unknown signals and reasons), live `getDisplayDemand()` (viewport × DPR bands) and `describeRenderBudget()` (the unchanged quality profile plus `surface`/`legacy-pointer-density`/`capability`/`policy` limiters). The 3 MP backing-store gate and coarse-pointer DPR-3 gate remain. `getGraphicsFeatures()` probes WebGL2 then WebGL1, reports scalar limits and releases the context without reading identity strings. `recordFrameSample()` in `adaptive-performance.js` is fed by `createAdaptiveFrameLoop` and the cosmic engine's existing frame function; the observational snapshot is `warming`/`healthy`/`strained`/`critical` with a 1.5 s window, 2 s warm-up, 1 s hysteresis and hidden/gap/target resets. It adds no loop, timer or listener and does not adapt anything.
- **Resource readiness:** `app/lib/resource-readiness.js` is the one site-wide preparation hub. Experiences register `id`, `version`, routes, dependencies and resources; the built-in adapters are image (load + decode), code (Next router prefetch) and audio (existing Howler/Web Audio prepare, never playback). Registration manifest: `app/lib/resource-readiness-manifest.js`; invisible mount: `components/ResourceReadiness.jsx` in the root layout. It reuses the adaptive plan's `maxParallelRequests`, `prefetch`, `audioPreload` and release registry,   adds no capability probe or subscription of its own, deduplicates in-flight and completed requests by kind + target + version, and reports `fetched`/`initialized`/`ready`/`failed`/`skipped`. Policy skips are re-evaluated rather than cached, retry wake-ups are deadline-driven, a failed resource backs off briefly, and a higher-priority caller upgrades an in-flight background run. No service worker or storage layer exists; the hub relies on the existing immutable asset caching.
- **Lucky Meter renderer:** `components/cosmic-event-engine.js` composites two additive WebGL surfaces (far behind the interface, a pointer-transparent near layer above it) using the shared shaders in `app/lib/gpu-particles.js`. The meter is one Three.js scene (`app/lib/lucky-meter/meter-scene.js`) built through `createCreativeSurface`, with the complete CSS meter as the first paint, no-WebGL and context-loss fallback. `components/lucky-meter-ring-engine.js` and `app/lib/lucky-meter/vessel-scene.js` are retired. `resolveRenderQuality` supplies the tier, DPR cap, particle scale, near-layer availability, haze and spark budget. `app/lib/lucky-meter/storyboard.js` is the single timing source: wheel 4,400 ms / stops 6,300 ms, percentage 9,400 ms from 1,900 ms, stored result at 11,300 ms, pour 2,000 ms, 1,500 ms pause, 1,500 ms beam, celebration 12,000 ms for every tier and a 1,300 ms Spark delay; the total is emergent. `CELEBRATION_MS` (D12) deliberately ignores a stored legacy `stageDurationMs`, so a refreshed celebration restarts at 12,000 ms.
- **Audio:** Howler and browser Web Audio API where already used. Lucky Meter audio assets are genuine recordings; additions carry a provider, item, licence, acquisition date and derivative record in `public/sounds/lucky-meter-cinematic-audio-sources.md`.
- **Database:** Neon PostgreSQL through the serverless driver.
- **Hosting/build:** Cloudflare Pages hosting with OpenNext Cloudflare build tooling and Workers runtime support.
- **ISR revalidation queue:** The existing OpenNext Durable Object queue is wrapped by queueCache with a five-second regional Cache API TTL and acknowledgement-before-cache behavior. This suppresses repeat dispatches for the same page/content-version identity after the Durable Object accepts the request; it does not replace the Durable Object's in-flight deduplication or guarantee elimination of every R2 write-rate-limit event.
- **Payments and email:** Stripe Checkout and Resend.
- **Public-form protection:** Cloudflare Turnstile, alongside existing validation, sanitization and rate limits.

## Testing and Verification
- **Unit/component:** Vitest and Testing Library.
- **Browser/e2e:** Playwright Test with the repository's configured desktop, mobile-390 and mobile-412 projects and committed visual baselines. Normal QA uses `playwright.config.ts` (`pnpm test:visual`); `pnpm test:visual:swiftshader` selects the opt-in `playwright.swiftshader.config.ts` for software-rendered graphics investigations. The layer model, capability contract and fallback ladder are documented in `docs/graphics-rendering-architecture.md`.
- **Direct agent browser interaction:** Use the vendored Microsoft Playwright CLI skill and local pnpm exec playwright cli command when available. Browserless is the connected remote-browser option and fallback under the rules in AGENTS.md. Do not assume Browserbase is connected.
- **Repository gate:** `./freebuff-verify.sh` runs the frozen install, Spec Kit gate, every Python checker suite, TypeScript, the full Vitest suite, docs tests, the Next.js build and a 495 MiB size check. It does not run Playwright, OpenNext, DevSkim or deployment. Visual QA does not depend on that script; its always-on job is named **Application Verification** and runs the Python suites, full Vitest, docs tests and `tsc`.
- **PR applicability:** `.github/scripts/pr_applicability.py` decides, fail-closed, whether a change set can affect the production build; `.github/scripts/compute-applicability.sh` composes it with `classify-visual-changes.sh` and the declared `visual_impact` from the trusted base checkout. The OpenNext workflow's `changes` job gates the build on `build_required != 'false'`; `merge_group` and `workflow_dispatch` always build. Verification Integrity and the report audit receive the same flags. A required-but-skipped check blocks; a proven-inapplicable check is labelled `SKIPPED — NOT APPLICABLE` with its trusted authority and reason, never `PASSED`, while the category stays `PASSED` when every other applicable requirement passes. An observed failure always outranks the skip.
- **Playwright execution:** the two shards are planned per whole spec file by `.github/scripts/plan-playwright-shards.mjs` from `tests/visual/shard-plan.json` (seeded from Visual QA run 45076917637, with per-file durations summed across the three projects), with a union/no-duplicate guard and a fail-closed fallback. The shard is passed as an anchored file filter, because Playwright treats positional arguments as regexes and a bare `gold-cta.spec.ts` would also match `sitewide-gold-cta.spec.ts`. `summarize-playwright-timings.mjs` writes per-spec durations/flakes from the JSON reporter; `select-visual-specs.mjs` and `tests/visual/impact-map.json` list the affected specs in shadow mode only while every spec still runs. All 16 specs, three projects and three committed baselines are unchanged; `--forbid-only` is set. Each CI shard keeps two workers: a third runs all three projects of a long spec at once and the Lucky Meter spec measured 587 s at two workers versus 409 s at three, but on the four-CPU CI runner that third worker starved the spec (three hard mobile failures, seven retry-only passes), so two is retained. Splitting that file into more specs did not beat the shard floor at three workers, so every spec and baseline stays unchanged. The audit's bounded wait is 1800 s with a 40-minute job timeout, longer than a shard's 25-minute hard timeout, and it waits for an applicable browser group even before its first shard check run exists.
- **Visual QA timing report:** `report_visual_qa_install_timings.py` reports each Visual QA job's `Install dependencies` duration against the PR #1914 baseline (8 s verification, 7 s per shard) plus pnpm/Chromium cache states for a run ID; it is read-only and supports offline fixtures.
- **QA infrastructure:** `check_qa_pr_scope.py` validates the exact path manifest, approvals and browser evidence from trusted base-branch code. Browser evidence is required for frontend/rendering paths; known CI-only paths under .github/ and Next.js API handlers under app/api/ and pages/api/ are excluded unless visual_impact.required: true explicitly forces it. `review_pr_changes.py` scans added patch lines for a narrow set of high-confidence secrets and advisory quality risks; it is not a replacement for DevSkim or CodeQL. Secret-like excerpts are redacted before reports are written. Each finding carries a severity, a confidence and a `confirmed`/`potential` classification, findings collapse by path and line, and the report counts collapsed duplicates. It also flags committed focused tests, promises floated through `forEach(async ...)`, empty catch blocks, and unused import bindings in fully added files. Every finding carries a concrete `suggestion` (rewritten line, awaited `for...of` form, `catch (error)` handler, unused binding to delete, replacement API, package plus lockfile update), and the report is published as one sticky pull request comment that is updated in place. Its `suggested_verification` mirrors `classify-visual-changes.sh`: Playwright visual work is suggested only for rendering paths, performance measurement only for performance-sensitive paths, and documentation, tooling, CI or unit-test-only changes are told that no browser verification is suggested. The shared `.github/scripts/qa_skip.py` contract owns the per-item skip label, the closed authority list and the narrow verified-Dependabot exemption; every checker imports it so the semantics cannot drift. Visual QA installs Chromium unconditionally with `pnpm exec playwright install --with-deps chromium` under a cache key derived from the installed Playwright version; there is no custom cache validator or hardcoded revision. `scripts/playwright-cli.sh` and `scripts/setup-playwright-agent.sh` compare `node_modules/.pnpm/lock.yaml` with `pnpm-lock.yaml`, so a Playwright update by Dependabot or the owner reinstalls automatically instead of running the previous tree.
- **Deployment:** A deploy command or successful build does not authorize deployment. Follow AGENTS.md approval boundaries.

## Architecture and Data Boundaries
- Next.js App Router contains the user-facing experiences and server routes.
- Neon is the existing PostgreSQL provider. Do not migrate providers or alter production data without explicit authorization.
- Stripe processes payments for digital experiences; it does not sell lottery tickets or accept wagers.
- Resend delivers transactional gift/email messages.
- Cloudflare Pages is the hosting platform. Do not introduce a hosting migration as part of unrelated work.
- Treat credentials and secret values as opaque. Never place them in source, logs, reports or Memory Bank files.

## Hard Constraints
- **Production build size:** The measured production build output must remain strictly below **495 MiB**. This is the repository's hard cap, defined in AGENTS.md; it is not a .docs directory limit. Measure and report every production build.
- Preserve current UI, artwork, functionality, security controls, integrations and responsive behavior unless the task explicitly authorizes a change.
- Keep .docs/ read-only unless the owner explicitly authorizes a library change.
- AGENTS.md is the sole authoritative governance document. This file records technical facts only and must not duplicate its workflow rules.
