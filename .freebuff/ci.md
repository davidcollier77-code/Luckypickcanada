## 2026-09-06 - Fixing CI failures due to pnpm v10 strict build rules
**Learning:** `pnpm` version 10 enabled strict supply chain security features by default, blocking execution of `postinstall` lifecycle scripts (e.g. `esbuild`, `playwright`, `workerd`). When CI uses floating version pins (like `npm install -g pnpm`), pulling down major version releases implicitly can break builds with `ERR_PNPM_IGNORED_BUILDS`. Setting `ignore-scripts=true` circumvents the crash but causes problems downstream for things that require those native dependencies.
**Action:** Pinned `pnpm` using `pnpm/action-setup@v4` in CI configurations to `10.30.3`. Properly documented `pnpm.onlyBuiltDependencies` allow-list explicitly within `package.json` to instruct pnpm to selectively trust these dependencies. Additionally, added `"packageManager": "pnpm@10.30.3"` to `package.json` to maintain lockfile compatibility.
