# Implementation Plan — Cloudflare preview manifest runtime repair

## Selected Task Group
`troubleshooting` — repair a confirmed production runtime failure.

## Verified Evidence
- Cloudflare logs for GET `/crystal-ball` show `Unexpected loadManifest(/.next/server/preview-props.json) call!` from `NextNodeServer.getPreviewProps` during server initialization.
- The starting dependency state used Next.js `16.4.1`, `@opennextjs/cloudflare@1.20.6`, and Wrangler `4.141.0`.
- Upstream OpenNext PR #1356 fixes build-time inlining of `preview-props.json` for Next.js 16.4+. Release 1.20.13 includes that fix and requires Wrangler `^4.148.0`.
- A first validation attempt exposed an additional dependency-resolution issue: `minimatch@9.0.9` was resolved with `brace-expansion@5.0.12`, which lacks the default export that minimatch 9 imports. A narrow `minimatch@9.0.9>brace-expansion: 2.1.7` override was added, then the lockfile was regenerated by pnpm 10.30.3.

## Approach
1. Upgrade the pinned adapter and Wrangler versions to a mutually compatible release set containing the upstream manifest fix.
2. Keep the minimatch/brace-expansion dependency pair API-compatible with the narrow, version-scoped override.
3. Regenerate `pnpm-lock.yaml` using pnpm 10.30.3; do not hand-edit dependency resolutions.
4. Run the repository OpenNext validation/build and inspect CI results.
5. Review the final diff for unrelated changes and record exact verification status in the PR.

## Constraints
- No direct production deployment, no merge, and no secret or environment-variable changes.
- Preserve website visuals, wording, routes, and application behavior.
- Enforce the 495 MiB `.next + public` hard maximum.
- A successful build alone is not proof of live runtime recovery; production remains unverified until the owner approves deployment and the homepage plus `/crystal-ball` are checked.
